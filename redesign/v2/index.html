ShareTrip · Bookings

Making booking retries safe

Problem
Booking requests can arrive more than once, after a timeout or a repeated tap. A repeat must not take another room.
What we did
We use the booking identifier to recognise repeats. A MySQL named lock orders work on the same booking, and a transaction groups the database changes. Cancellation follows the same rules.
Result
A repeated submit returns the existing booking, and inventory changes once. Add a measured result if you have one

ShareTrip · Hotel search

Speeding up hotel search

Problem
Search processed hotel IDs in chunks, one after another, so later chunks waited for earlier ones.
What we did
The search returns a session at once and fills it in the background. Chunks run concurrently within a bound, smaller early chunks bring first results sooner, and shared counts update atomically.
Result
Results appear while the rest of the search continues. Add a measured result if you have one
