AI agents

AI agents write many of my first drafts. I stay responsible for every line that ships. This page shows the method I use, at ShareTrip and on side projects.

The loop

  1. PlanI approve it first
  2. BuildOne agent, one worktree
  3. ReviewA different provider
  4. FixOne round
  5. CheckReal tests, real results
  6. MergeI do this part

Every change follows the same path. The agents do the middle four steps. The first and the last are mine.

The rules

  1. One agent for small work. I split a task only when its parts are independent.
  2. No worker starts before I approve a plan. The plan states the machine load, the task weight, the number of workers, and the model for each one.
  3. The cheapest model that can finish without rework. The strongest model is for unclear requirements and risky changes.
  4. Each writer gets its own worktree. Two agents never edit the same checkout.
  5. A different provider reviews the code. An agent that wrote a change tends to agree with it.
  6. One review round, one fix round. A second round is only for a serious finding that is still open.
  7. Agents never merge. They do not push to shared branches. I integrate the work.
  8. Checks must really run. A report lists what passed, what failed, and what was skipped.
  9. Agents never load production secrets. They inspect a live system only with my approval.

Threads

Skills

A skill is a written procedure that an agent loads for one kind of task. I write mine after I catch myself explaining the same thing twice. Every agent on every machine then follows the same steps.

  • InvestigateExplain the code, the logs or the bug first. An investigation is not permission to fix.
  • Inspect systemsRead databases, logs and storage safely: my approval first, careful credentials, careful data.
  • Verify changeChoose checks that prove the change works when unit tests cannot.
  • OrchestratePlan delegated work: the split, the model for each worker, isolation, and recovery.
  • ReleasePromote changes across branches and repositories, then verify the deployment.
  • HandoffPack the context of unfinished work so it continues in a new thread or on another machine.
  • Idea batchSuggest numbered improvements for my setup, then build the ones I pick.

What stays with me

  • The requirements, and the question of what to build.
  • The architecture and the trade-offs.
  • The final read of every diff.
  • The merge, and the result after it.

On my team sheet, the AI agents play false 9: they drop deep and set up the finish. The manager picks the team and owns the result.
